# 刚好·净省凑单 v1.5 交付说明

本项目是普陀创新挑战赛「刚好·净省凑单」的本地产品原型。1.3 将可成交购物车的净省推荐与未达起送的补单分开：前者必须降低实付；后者展示达到起送后的实付及相对旧估算的变化，**原车不可下单，变化不计为净省**。1.4 补齐「AI 智能省钱场景」对推荐算法与实时计算的演示落点；1.5 把 BP 中的「超时降级，不阻塞下单」做成已实现、已测量的引擎能力。

## 本次完善

| 模块 | 已实现行为 |
| --- | --- |
| 起送补单 | 默认起送价 ¥25，未达门槛时寻找可起送方案，展示补单后实付、额外增支或估算减少 |
| 用户偏好 | 最多加购 0–4 件、商品预算、排除商品、「支出更低／购买件数更少／符合我的偏好」；无可行解时明确说明 |
| 偏好推荐（演示级） | 服务端从本机演示事件统计品类权重（采纳/忽略/撤销分计，截断 ±3），按权重微调方案展示次序；方案内容与金额不变，响应带权重快照，界面标注演示级 |
| 精确组合 | 在给定候选、库存与约束内枚举最多四件数量组合，支持同品多件，返回最多三种方案 |
| 实时降级求解 | 目录超过 24 候选自动按价格分层轮转剪枝，搜索超 90ms 截断；方案仍经同一计价与约束校验，接口返回 `search.degraded` 明细，界面标注「实时预算内求解」；50 候选（API 上限）下约 60ms 得到与全量穷举一致的首选目标 |
| 完整计价 | 按分计算满减、优惠券、限时价、配送和商品包装费；包装费缺省为 0 |
| 方案比较 | 比较加购商品、数量、成本和最终实付；净省与起送分支使用各自金额说明 |
| 采纳与撤销 | 采纳前复核报价，最近一次采纳可撤销一次并恢复购物车；原记录保留 |
| 历史与看板 | 两类采纳分别计数，起送补单采纳呈现为「起送转化（不可下单→可下单）」；起送事件不显示净省，撤销起送不显示净省扣回；兼容旧净省记录；看板可二次确认后清空本机演示事件与性能样本 |
| 实时计算 | 方案区显示本次服务端计算耗时，查看建议弹窗保留候选数、组合数、P99 与往返耗时 |
| 本地持久化 | 服务端原子落盘，幂等处理重试，刷新恢复购物车及待确认状态 |
| 算法验证 | 独立计价／穷举参照、固定种子合成场景、基线比较与性能报告 |
| 本地任务评估 | 固定起送／满减任务，手动或智能方式，浏览器保存任务用时、选择与反馈，支持 JSON/CSV 导出 |
| 启动与导航 | 一个本机 3000 服务提供 API、演示中心和六个页面，公开文件使用白名单；演示中心标签切换不刷新并推动子页面数据刷新，宽屏自动并排联动体验与看板，内置演示步骤速查，服务未启动时提示启动方式 |

默认场景保持：商品小计 ¥48，常规时段实付 ¥35，采纳 ¥2 米饭净省建议后实付 ¥32，预计净省 ¥3。高峰配送附加费同时影响前后金额。PC 与静态移动端仍为纯前端单件基础原型，1.5 完整功能在 API 联动版。

## 指标与证据边界

有效采纳数包含未撤销的净省采纳与起送补单，分别提供分类数；采纳率为有效采纳 ÷（有效采纳 + 忽略）。已撤销与未决定建议不进入分母。

累计预计净省只累加有效净省方案的正净省；起送补单贡献 0。平均采纳净省以**全部有效采纳数**为分母，包含起送补单的 0 贡献。近 7 天金额按北京时间的采纳日期汇总并剔除已撤销采纳。起送补单的估算减少也不转换为净省。

以上来自本机联动演示，不代表真实订单、支付、用户收益或准确率。平均耗时与 P99 是当前进程最近最多 1000 次实际计算；服务重启重新采样。基准报告只验证合成场景下实现与参照的一致性及样本耗时，不是生产延迟承诺。

「精确」限于已实现计价规则、给定目录和最多四件的有限搜索空间。搜索规模随候选数增长，未实现全平台最优、跨店券、账户专属优惠或经用户数据训练的偏好模型。

任务评估使用固定示例，不会随机分组。匿名编号、计时与反馈记录只保存在当前浏览器，求解和金额复算走独立本机研究接口，不进入业务采纳率、累计净省、操作历史或业务性能窗口。研究员需自行安排任务方式和顺序；未招募参与者的记录属于演示数据。该工具不代表已开展真实用户实验，也不提供平台交易效果证据。

## 启动与演示

需要 Node.js 20+。双击 `start-demo.bat`；或进入 `backend`，执行 `npm install`、`npm start`。依赖仍只有 Express 与 CORS。

| 页面 | 本机地址 |
| --- | --- |
| 演示中心（根路径直达，标签切换不刷新） | [demo.html](http://127.0.0.1:3000/demo.html) |
| 完整联动演示 | [mobile-api.html](http://127.0.0.1:3000/mobile-api.html) |
| 实时演示看板 | [dashboard.html](http://127.0.0.1:3000/dashboard.html) |
| 操作记录 | [history.html](http://127.0.0.1:3000/history.html) |
| 本地任务评估 | [research.html](http://127.0.0.1:3000/research.html) |
| PC 基础原型 | [index.html](http://127.0.0.1:3000/index.html) |
| 移动端基础原型 | [mobile.html](http://127.0.0.1:3000/mobile.html) |

1. 点击「满减净省示例」，比较方案，核对明细与 ¥35 → ¥32 的净省；采纳后到看板检查变化。
2. 修改件数、成本、排除项及排序偏好，观察约束影响；0 件表示不加购。
3. 点击「起送补单示例」，商品小计 ¥20，低于默认 ¥25 起送价，查看补单实付与估算变化；采纳后确认采纳数增加而累计净省不增加。
4. 撤销采纳，核对购物车恢复、分类计数扣回与原记录保留；历史页按类型筛选或加载更多。
5. 点击「满减净省示例」，打开方案后选择「不加购」，查看忽略数，再导出 JSON／CSV。

看板约每 2 秒更新，历史页进入或刷新时更新；失败时保留旧快照并明确提示。恢复示例不清空历史，关闭后端窗口停止服务。

任务评估另用固定预算 ¥10、最多 3 件的两类任务。填写匿名编号、选择手动或智能方式后完成任务和反馈，可导出或清除本浏览器记录；不创建订单或支付。完整步骤与数据边界见 [README 的本地任务评估说明](README.md#本地任务评估)。
