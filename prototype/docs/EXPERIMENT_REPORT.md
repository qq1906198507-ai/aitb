## 研究问题与边界

验证给定候选、库存、加购预算、排除项、策略和最多四件限制下，起送达标方案或正净省方案是否满足约束、计价是否可复算、排序目标是否与独立穷举一致。同时观察不同规模下的本机计算耗时。本实验使用构造及伪随机数据，没有真实用户、订单、支付或平台数据；不能证明转化率、满意度或交易规模提升。

## 基线与指标

## 实时降级（v1.5）

候选超过 24 个时按价格分层轮转保留（低价层优先，逐层补足以覆盖各价格档位），搜索超过 90ms 截断；返回方案仍经同一计价与约束校验。在 50 候选（API 上限）场景：全量穷举 316,250 组合 / 954.5ms，降级路径评估 20,474 组合 / 65.3ms（剪枝=是，截断=否），首选目标与全量穷举**一致**。降级路径不声称全空间最优，只保证方案可行、计价同源与不阻塞下单；是否降级由目录规模决定并由接口如实标注。

本次最优性只针对给定候选、最多四件、原购物车不变以及当前简化优惠规则。性能覆盖 5、10、20、50 个候选，已达 API 商品数组的 50 项上限；50 候选的全量穷举在本机约为 1–2 秒每次同步计算（见上表），生产环境应依赖上一节的实时降级路径，其延迟与目标一致性已在同一规模测量。未包含跨店、复杂优惠互斥组、满减与券的多种门槛口径、真实库存预留和账户资格，也未测多用户并发、网络或长期运行。固定种子场景集有助复现，不代表真实商品/优惠分布。v1.4 新增的偏好加权重排（算法模型第 5.1 节）是展示层启发式，不改变方案集合与金额，不在本合成实验范围内，其行为由 API 集成测试覆盖；本报告不声称该重排提升采纳率、转化或用户收益。下一步应补独立真实规则样例、平台对账数据与用户任务实验，并按起送和净省两类目的分别评估。
